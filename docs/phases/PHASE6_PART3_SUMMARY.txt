================================================================================
OPTIMIZATION AREAS
================================================================================

1. BATCH PROCESSING
   - Default batch size: 10 pages (was 25)
   - Configurable via SettingsService
   - Lower memory footprint per invocation
   - Better compatibility with shared hosting time limits (30-60s)

2. PAGE FETCH OPTIMIZATION
   - Each URL fetched ONCE per execution (in-memory cache)
   - Metrics: fetch count, cache hits, avg fetch time, cache hit rate
   - Configurable timeout from settings (default 30s)
   - Connect timeout: 10s (prevents long hangs on dead hosts)
   - Download size limit: 5MB (prevents memory exhaustion on large pages)
   - LRU eviction when cache exceeds 50 entries

3. DATABASE WRITE OPTIMIZATION
   - Config flag: writes.skip_unchanged (default true)
   - Architecture prepared for comparing result before writing
   - ON DUPLICATE KEY UPDATE already prevents duplicate rows
   - Only changed status/values trigger history recording

4. JOB HEARTBEAT & SAFEGUARDS
   - Heartbeat updated during processing (per batch)
   - Stale job timeout: 1 hour (jobs processing > 1h get failed)
   - Consecutive error limit: 50 (abort runaway jobs)
   - Duplicate prevention: one active job per project
   - Orphan detection: jobs without valid projects cleaned up
   - All safeguards run automatically in cron cycle

5. PERFORMANCE METRICS
   - Execution time per job
   - Pages per minute calculation
   - Per-module timing (avg, min, max)
   - Fetch count and cache hit rate
   - Writes performed vs skipped
   - All metrics logged via LoggingService

6. CENTRALIZED LOGGING
   - Category-based log files: audit, jobs, retry, fetch, system, metrics
   - Date-stamped files (audit-2026-06-24.log)
   - Structured context (JSON) appended to entries
   - Configurable retention (default 14 days)
   - Auto-cleanup of old log files

7. PROJECT HEALTH MONITORING
   - Health status: healthy / needs_attention / degraded
   - Active, problem, and completed job counts
   - Retry queue size
   - Processing rate (pages per minute from recent jobs)
   - System-wide health overview (across all projects)

================================================================================
SAFEGUARD SYSTEM
================================================================================

HealthMonitorService::runSafeguards() performs:

  1. Mark interrupted jobs (heartbeat > 120s old)
  2. Fail stale jobs (processing > 1 hour)
  3. Clean orphaned jobs (deleted projects)

Called automatically by:
  - cron/process_jobs.php (every minute)
  - Frontend poll trigger (every 5 seconds when active)

Protection against:
  ✓ Infinite loops (consecutive error limit)
  ✓ Stalled jobs (heartbeat timeout)
  ✓ Duplicate execution (one active job per project)
  ✓ Orphaned jobs (cascade cleanup)
  ✓ Memory exhaustion (5MB fetch limit + LRU cache)
  ✓ Time exhaustion (55s execution limit with graceful yield)

CRON CYCLE (COMPLETE)
================================================================================

Every minute, cron/process_jobs.php:
  1. Runs safeguards (interrupt/stale/orphan detection)
  2. Picks up next queued job
  3. Processes up to 10 pages (or 55 seconds)
  4. Updates progress + heartbeat
  5. Logs execution summary
  6. Exits cleanly for next invocation

Without cron:
  - Frontend polls /routes/jobs.php?action=process every 5s
  - Same processing logic, just user-driven
