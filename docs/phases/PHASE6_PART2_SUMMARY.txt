================================================================================
SMART RETRY LOGIC
================================================================================

CORE RULE: Never rerun successful pages.

Decision flow per page/module:
  1. Does the page already have PASS result? → SKIP
  2. Is retry status 'retry_exhausted'? → SKIP
  3. Is retry_count < max_retries? → RETRY
  4. Otherwise → SKIP

Error classification:
  timeout           → curl timeout or slow response
  connection        → connection refused, unreachable
  invalid_response  → HTTP 4xx/5xx
  malformed_html    → DOM parsing failures
  processing        → module-internal errors
  unknown           → unclassified

Retry state machine:
  [First failure] → retry_pending
  [Retry attempt] → retrying
  [Retry fails]   → retry_failed (still < max) OR retry_exhausted (>= max)
  [Retry succeeds] → resolved
  [Manual reset]  → retry_pending (re-enables retries)

================================================================================
AUTO RESUME SYSTEM
================================================================================

When a job is interrupted (heartbeat timeout) or paused:
  - The job retains its last_page_id (last successfully processed page)
  - ResumeService re-queues the job with status='queued'
  - JobProcessor picks it up and continues from last_page_id
  - No pages are re-processed

Resume workflow:
  1. System detects interrupted job (heartbeat > 120s old)
  2. Marks job as 'interrupted'
  3. UI shows "Resume" button
  4. User clicks → ResumeService::resumeJob() → re-queues
  5. JobProcessor picks up → starts from last_page_id + 1
  6. Previously processed pages are skipped

================================================================================
API ENDPOINTS (NEW)
================================================================================

POST /routes/jobs.php?action=resume
  Params: job_id
  Response: { success, message }
  (Resume a single interrupted/paused job)

POST /routes/jobs.php?action=resume_all
  Params: project_id
  Response: { success, resumed_count, message }
  (Resume all interrupted jobs for a project)

POST /routes/jobs.php?action=retry
  Params: project_id, modules, keyword (optional)
  Response: { success, job }
  (Create a retry job targeting only failed pages)

GET  /routes/jobs.php?action=retry_stats&project_id=X
  Response: { success, stats, error_types }
  (Retry statistics and error distribution)

GET  /routes/jobs.php?action=recoverable&project_id=X
  Response: { success, recoverable: {has_resumable_jobs, has_retryable_pages, ...} }
  (Check if project has any recoverable work)

================================================================================
PERFORMANCE
================================================================================

Retry system is optimized for:
  - Shared hosting (batch + time-limited processing)
  - Large projects (indexed queries on page_retry_tracking)
  - Low memory (processes one page at a time during retry)
  - Minimal I/O (only fetches pages that actually need retry)

Key optimization: UNIQUE KEY (project_page_id, module_name) with
ON DUPLICATE KEY UPDATE means no duplicate tracking rows ever accumulate.

================================================================================
TESTING
================================================================================

To test the retry system:

1. Run an audit with some URLs that will fail (404s, timeouts):
   POST /routes/jobs.php?action=create
   project_id=1&modules=h1,meta

2. Process the job:
   GET /routes/jobs.php?action=process

3. Check retry stats:
   GET /routes/jobs.php?action=retry_stats&project_id=1

4. Retry failed pages:
   POST /routes/jobs.php?action=retry
   project_id=1&modules=h1,meta

5. Check recoverable work:
   GET /routes/jobs.php?action=recoverable&project_id=1

To test auto-resume:
1. Start a job, then kill the PHP process mid-execution
2. Wait 2+ minutes (heartbeat timeout)
3. The next cron run will mark it as interrupted
4. Use resume endpoint or UI button to continue
