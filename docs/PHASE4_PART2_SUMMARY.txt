================================================================================
MODULE 1: NOINDEX AUDIT
================================================================================

PURPOSE:
Detect and report on page indexability status by analyzing robots meta tags.

DETECTION LOGIC:
- Fetches page HTML
- Extracts <meta name="robots"> tag
- Parses directives: noindex, index, nofollow, follow
- Stores robots content, index status, and follow status

RESULT STATUSES:
┌─────────┬────────────────────────────────────────────────────┐
│ PASS    │ Page is indexable (no noindex directive)          │
│ WARNING │ Mixed or unclear directives detected              │
│ FAIL    │ Noindex directive found (page blocked from index) │
│ ERROR   │ Page unavailable or fetch failed                  │
└─────────┴────────────────────────────────────────────────────┘

STORED DATA (raw_data_json):
{
  "robots_content": "noindex, nofollow",
  "index_status": "noindex",
  "follow_status": "nofollow",
  "has_robots_tag": true
}

ERROR CASES:
{
  "error": "Failed to fetch page: Timeout",
  "index_status": "unknown",
  "follow_status": "unknown"
}

================================================================================
MODULE 2: FAQ SCHEMA AUDIT
================================================================================

PURPOSE:
Detect FAQ schema markup and FAQ content patterns on pages.

DETECTION LOGIC:
- Searches for FAQPage schema in JSON-LD
- Detects structured FAQ data
- Identifies FAQ content patterns
- Extracts schema snippets (limited size)

RESULT STATUSES:
┌─────────┬────────────────────────────────────────────────────┐
│ PASS    │ FAQ schema found (FAQPage detected)               │
│ WARNING │ FAQ content found but schema missing              │
│ FAIL    │ Expected FAQ not found                            │
│ ERROR   │ Page fetch failed                                 │
└─────────┴────────────────────────────────────────────────────┘

STORED DATA (raw_data_json):
{
  "schema_found": true,
  "schema_type": "FAQPage",
  "schema_count": 5,
  "content_found": true,
  "schema_snippet": "..."
}

ERROR CASES:
{
  "error": "Failed to fetch page: Connection timeout",
  "schema_found": false,
  "content_found": false
}

MODULE ARCHITECTURE
================================================================================

Both modules follow the same clean architecture pattern:

/app/Modules/NoindexAudit/
├── NoindexAuditController.php    (HTTP request handling)
├── NoindexAuditService.php       (Business logic orchestration)
├── NoindexAuditProcessor.php     (HTML parsing & analysis)
├── NoindexAuditRepository.php    (Database operations)
└── NoindexAuditValidator.php     (Input validation)

/app/Modules/FaqSchemaAudit/
├── FaqSchemaAuditController.php  (HTTP request handling)
├── FaqSchemaAuditService.php     (Business logic orchestration)
├── FaqSchemaAuditProcessor.php   (Schema detection & parsing)
├── FaqSchemaAuditRepository.php  (Database operations)
└── FaqSchemaAuditValidator.php   (Input validation)

CONTROLLER ACTIONS:
- audit_page       → Audit single page
- audit_pages      → Audit multiple pages (batch)
- audit_project    → Audit entire project
- results          → Get audit results
- stats            → Get audit statistics
- delete           → Delete audit result

DATABASE STORAGE
================================================================================

TABLE: page_audit_results

Stores all audit results with module_name differentiation:

┌──────────────────────┬──────────────────────────────────────────────┐
│ Field                │ Description                                  │
├──────────────────────┼──────────────────────────────────────────────┤
│ id                   │ Auto-increment primary key                   │
│ project_page_id      │ Foreign key to project_pages                 │
│ module_name          │ 'noindex_audit' or 'faq_schema_audit'        │
│ result_status        │ PASS, WARNING, FAIL, ERROR                   │
│ result_value         │ Human-readable summary                       │
│ raw_data_json        │ Complete JSON result data                    │
│ checked_at           │ Timestamp of audit execution                 │
│ created_at           │ Record creation timestamp                    │
│ updated_at           │ Record update timestamp                      │
└──────────────────────┴──────────────────────────────────────────────┘
