================================================================================
MODULE 1: LOREM IPSUM AUDIT
================================================================================

PURPOSE:
Detect placeholder content and dummy text that shouldn't be on production sites.

DETECTION KEYWORDS (Default):
- lorem ipsum
- dolor sit amet
- consectetur adipiscing
- placeholder text
- sample content
- dummy content
- dummy text
- test content
- example text
- filler text

DETECTION LOGIC:
- Fetches page HTML
- Extracts text content (removes scripts/styles)
- Searches for keywords (case-insensitive)
- Counts occurrences
- Extracts snippets with context

RESULT STATUSES:
┌──────┬────────────────────────────────────────────────────┐
│ PASS │ No placeholder content found                       │
│ FAIL │ Placeholder content detected                       │
│ ERROR│ Page unavailable or fetch failed                   │
└──────┴────────────────────────────────────────────────────┘

STORED DATA (raw_data_json):
{
  "keywords_checked": [...],
  "total_checked": 10,
  "matches_found": 2,
  "total_occurrences": 5,
  "matches": [
    {"keyword": "lorem ipsum", "count": 3},
    {"keyword": "placeholder text", "count": 2}
  ],
  "snippets": [
    {"keyword": "lorem ipsum", "snippet": "...context lorem ipsum context..."}
  ]
}

FEATURES:
✓ Configurable keywords (extensible for future)
✓ Context-aware snippet extraction
✓ Case-insensitive matching
✓ Unicode support (UTF-8)
✓ Performance optimized text extraction
✓ Limit snippets to prevent memory bloat

================================================================================
MODULE 2: STAGING URL AUDIT
================================================================================

PURPOSE:
Detect staging, development, and test URLs in production pages.

DETECTION PATTERNS (Default):
- staging.
- stage.
- dev.
- develop.
- development.
- test.
- testing.
- demo.
- localhost
- 127.0.0.1
- local.
- temp.
- temporary.
- preview.
- qa.
- uat.
- .local
- -staging.
- -dev.
- -test.

DETECTION LOCATIONS:
- Links (href attributes)
- Images (src attributes)
- Scripts (src attributes)
- Stylesheets (href attributes)
- Canonical tags

DETECTION LOGIC:
- Scans HTML source with regex
- Matches URLs against patterns
- Tracks source types
- Counts occurrences per URL
- Limits stored sources to prevent bloat

RESULT STATUSES:
┌──────┬────────────────────────────────────────────────────┐
│ PASS │ No staging references found                        │
│ FAIL │ Staging references detected                        │
│ ERROR│ Page unavailable or fetch failed                   │
└──────┴────────────────────────────────────────────────────┘

STORED DATA (raw_data_json):
{
  "patterns_checked": 19,
  "matches_found": 2,
  "total_occurrences": 5,
  "matches": [
    {"url": "https://staging.example.com/script.js", "count": 3},
    {"url": "https://dev.example.com/image.png", "count": 2}
  ],
  "sources": [
    {"url": "https://staging.example.com/script.js", "type": "script"},
    {"url": "https://dev.example.com/image.png", "type": "image"}
  ]
}

FEATURES:
✓ Configurable patterns (regex-based, extensible)
✓ Multiple source type detection
✓ URL deduplication
✓ Occurrence counting
✓ Source type tracking
✓ Limit stored sources (max 20)

MODULE ARCHITECTURE
================================================================================

Both modules follow the established clean architecture:

/app/Modules/LoremAudit/
├── LoremAuditController.php    (HTTP request handling)
├── LoremAuditService.php       (Business logic orchestration)
├── LoremAuditProcessor.php     (Text analysis & keyword search)
├── LoremAuditRepository.php    (Database operations)
└── LoremAuditValidator.php     (Input validation)

/app/Modules/StagingAudit/
├── StagingAuditController.php  (HTTP request handling)
├── StagingAuditService.php     (Business logic orchestration)
├── StagingAuditProcessor.php   (URL extraction & pattern matching)
├── StagingAuditRepository.php  (Database operations)
└── StagingAuditValidator.php   (Input validation)

CONTROLLER ACTIONS (Both Modules):
- audit_page           → Audit single page
- audit_pages          → Audit multiple pages (batch)
- audit_project        → Audit entire project
- results              → Get audit results
- stats                → Get audit statistics
- pages_with_lorem     → Get pages with placeholder content (Lorem)
- pages_with_staging   → Get pages with staging URLs (Staging)
- delete               → Delete audit result
