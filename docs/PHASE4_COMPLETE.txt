================================================================================
DATABASE SCHEMA
================================================================================

TABLE: page_audit_results

CREATE TABLE page_audit_results (
    id INT AUTO_INCREMENT PRIMARY KEY,
    project_page_id INT NOT NULL,
    module_name VARCHAR(50) NOT NULL,
    result_status ENUM('PASS','WARNING','FAIL','ERROR') NOT NULL,
    result_value TEXT,
    raw_data_json JSON,
    checked_at DATETIME NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY unique_page_module (project_page_id, module_name),
    INDEX idx_project_page (project_page_id),
    INDEX idx_module (module_name),
    INDEX idx_status (result_status)
);

================================================================================
API ENDPOINTS
================================================================================

COMMON ACTIONS (All Modules):
- audit_page       → Audit single page
- audit_pages      → Audit multiple pages (batch)
- audit_project    → Audit entire project  
- results          → Get audit results
- stats            → Get statistics
- delete           → Delete audit result

ENDPOINT PATTERN:
POST /routes/{module}_audit.php?action={action}

EXAMPLES:
POST /routes/h1_audit.php?action=audit_project&project_id=123
POST /routes/noindex_audit.php?action=audit_page&page_id=456
GET  /routes/faq_schema_audit.php?action=results&project_id=123

================================================================================
EXECUTION FLOW
================================================================================

USER ACTION:
1. Navigate to project.php?uuid={uuid}
2. Switch to URLs tab
3. Select desired modules (checkboxes)
4. Click "Run Selected Audits"
5. Confirm in dialog

SYSTEM PROCESSING:
1. JavaScript validates at least 1 module selected
2. Displays confirmation dialog
3. Runs audits sequentially (h1 → meta → noindex → faq)
4. Shows progress notification for each module
5. Stores results in database (INSERT or UPDATE)
6. Refreshes table to display results
7. Shows completion notification

ERROR HANDLING:
- Network failures → ERROR badge
- Timeouts → ERROR badge with timeout message
- HTML parse errors → ERROR badge with details
- Invalid responses → ERROR badge
